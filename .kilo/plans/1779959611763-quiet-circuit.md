# Knowledge Base Enhancement Plan for LLM

## Overview
The WorldQuant research agent already has a solid foundation for knowledge management. This plan focuses on enhancing the LLM's knowledge base by improving knowledge quality, preventing duplicates, and avoiding context overload while maintaining system performance. The enhancement is guided by a framework for extracting economic hypotheses, operator semantics, and validation principles from foundational research to foster genuine innovation.

## Current Knowledge Components
1. **Source Memory**: Distilled snippets from financial documents (source-memory.ts)
2. **Experience Buffer**: Learning from past simulations (research-engine.ts)
3. **Diversity Manager**: Pattern tracking to avoid correlation (diversity.ts)
4. **Reward System**: Learning from successful/unsuccessful outcomes
5. **Fingerprint Database**: Preventing exact expression duplicates

## Enhancement Opportunities

### 1. Improve Source Knowledge Quality with Hypothesis-Centric Approach
**Issue**: Current DISTILLED_SNIPPETS contains valuable information but could benefit from better curation, relevance scoring, and structuring around economic hypotheses rather than just facts.

**Solution**: Implement a knowledge scoring and structuring system that:
- Rates snippets by relevance to alpha generation and hypothesis formation
- Prioritizes implementation-specific guidance over general concepts
- Extracts and structures economic hypotheses from source materials (e.g., "Liquidity-Momentum hypothesis: Price trends are more likely to persist when accompanied by abnormal trading volume")
- Maps hypotheses to required data fields and operator primitives
- Removes low-value or redundant snippets
- Adds timestamp-based decay for time-sensitive information

### 2. Enhance Deduplication Mechanisms with Conceptual Awareness
**Issue**: While fingerprinting prevents exact duplicates, semantic and conceptual duplicates can still occur, leading to redundant alpha generation.

**Solution**: Improve similarity detection to catch conceptual redundancy:
- Enhance the `isSemanticallyRedundant` function in diversity.ts to include hypothesis-level comparison
- Add structural pattern matching that considers operator semantics and economic meaning
- Implement concept-level deduplication (not just expression-level) by comparing underlying economic ideas
- Create a hypothesis similarity metric that identifies when different expressions represent the same core economic concept

### 3. Implement Knowledge Relevance Scoring for LLM Context with Operator Semantics
**Issue**: The LLM receives all selected source snippets regardless of relevance to the current task, and lacks deep understanding of operator semantics for creative fusion.

**Solution**: Add task-aware knowledge retrieval with semantic understanding:
- Score snippets by relevance to current hypothesis/style/context
- Dynamically adjust snippet count based on relevance scores
- Implement snippet importance weighting based on proven utility
- Integrate operator semantics knowledge to help LLM understand creative fusion possibilities (e.g., understanding that `rank()` establishes cross-sectional relative positioning)
- Provide creativity triggers that prompt novel operator combinations based on semantic understanding

### 4. Add Knowledge Distillation Pipeline for Hypothesis Extraction
**Issue**: Manual curation of source snippets doesn't scale, and extracting actionable hypotheses from research papers requires specialized processing.

**Solution**: Create an automated knowledge extraction pipeline focused on hypothesis distillation:
- Process new documents (research papers, technical reports) to extract alpha-relevant economic hypotheses
- For each hypothesis, identify: core logic, required data fields, potential operator primitives, and related concepts
- Automatically score and filter extracted knowledge based on novelty and utility
- Integrate with existing source memory system as structured hypothesis entries
- Include human-in-the-loop validation for quality control of extracted hypotheses
- Build a hypothesis knowledge graph linking related economic ideas

### 5. Optimize Experience Buffer Utilization with Novelty Focus
**Issue**: Experience buffer stores all experiences equally regardless of learning value or novelty.

**Solution**: Implement experience prioritization:
- Score experiences by novelty (how different from existing hypotheses) and learning value
- Focus on high-information experiences for LLM context
- Implement experience clustering to reduce redundancy while preserving diversity
- Add forgetting mechanism for low-value or obsolete experiences
- Track which experiences lead to successful, unique alphas to reinforce valuable knowledge

**Implementation Details**:
1. Enhance ExperienceTuple type in types.ts to include:
   - noveltyScore: Measures how different this experience is from existing hypotheses (0-1)
   - learningValue: Measures the educational value of this experience (0-1)
   - usageCount: Tracks how many times this experience has been used for learning
   - lastUsedTimestamp: When this experience was last accessed
   - relevanceTags: Tags indicating what this experience is relevant to (e.g., "liquidity-momentum", "mean-reversion")

2. Modify addToExperienceBuffer in research-engine.ts to:
   - Calculate novelty score by comparing the experience's expression to existing hypotheses in source memory
   - Calculate learning value based on improvement magnitude and rarity of the modification strategy
   - Store the enhanced experience tuple with all new metrics

3. Implement experience retrieval logic that:
   - Prioritizes experiences with high novelty and learning value scores
   - Applies temporal decay to older experiences
   - Uses clustering to avoid redundant similar experiences in LLM context
   - Implements forgetting mechanism that removes low-value experiences when buffer exceeds threshold

### 6. Implement Innovation-Focused Validation Principles
**Issue**: Current validation focuses on syntax and basic performance without sufficient emphasis on statistical rigor and uniqueness.

**Solution**: Enhance validation pipeline with principles from foundational research:
- **Statistical Significance**: Calculate p-value for Information Coefficient (IC) to filter spurious correlations
- **Overfitting Detection**: Implement Combinatorially Symmetric Cross-Validation (CSCV) to estimate Probability of Backtest Overfitting (PBO)
- **Uniqueness Enforcement**: Measure correlation of new alpha's scores with baseline pool and penalize duplicates
- **Regime Awareness**: Incorporate market regime information to contextualize alpha performance
- **Parameter Stability**: Check robustness to parameter perturbations
- Create a multi-objective validator that evaluates proposals on: feasibility, performance, statistical significance, overfitting, and uniqueness

**Implementation Details**:
1. Add statistical significance calculation to validate IC values:
   - Compute t-statistic: t = IC × √(N-2) where N is number of observations
   - Derive p-value and reject if p-value > 0.05

2. Implement CSCV-based PBO estimation:
   - Partition returns data into symmetric combinations
   - Calculate IC for each combination
   - Estimate probability that observed IC is due to overfitting
   - Reject if PBO > 0.1

3. Enhance uniqueness check in diversity manager:
   - Calculate correlation of new alpha's returns with existing baseline
   - Apply penalty based on correlation magnitude
   - Integrate with existing diversity scoring mechanism

4. Add regime awareness to validation:
   - Incorporate current macro regime from research engine state
   - Adjust acceptance thresholds based on regime suitability
   - Provide regime context to LLM for hypothesis generation

5. Implement parameter stability checking:
   - Perturb key parameters (lookback windows, thresholds) by ±10%
   - Require IC to drop by less than 20% under perturbation

## Verification Criteria
1. Knowledge base growth doesn't degrade LLM performance
2. Duplicate knowledge insertion is prevented (exact, semantic, and conceptual)
3. LLM receives increasingly relevant and novel-promoting context over time
4. System maintains or improves alpha generation quality and uniqueness rate
5. Knowledge retrieval latency remains acceptable
6. Validation pipeline effectively filters spurious and overfitted alphas
7. Generated alphas demonstrate genuine innovation (low correlation with existing patterns)

## Success Metrics
- Reduction in duplicate/semantically/conceptually similar alpha generation
- Improvement in novel alpha discovery rate (alphas with unique economic hypotheses)
- Decrease in low-value simulation attempts (filtered by enhanced validation)
- Increased efficiency of LLM context utilization (higher signal-to-noise ratio)
- Maintenance of diversification effectiveness (diversity manager working optimally)
- Increase in statistically significant and robust alphas passing enhanced validation
